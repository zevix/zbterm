## Findings

1. **R5 is checked on the formatter, not on a live label of 24 h or more.** The kit runs only the `duration-format` debug command for values ≥ 24 h; no GUI label of that length is ever drawn (`R5_days.sh:22-29`). This is declared as a soft change in `notes--context.md`. Reading the code covers the gap: every duration label goes through `renderer/wall-clock.js:37` (call sites `renderer/app.js:5527, 7293, 7298-7299, 7382, 7388`).

2. **R13: the debug server's synthetic `click` gets past the guard.** The guard is CSS only (`renderer/index.html:734-740`), so programmatic clicks are not blocked. This is declared as a soft change. Real pointer clicks are blocked, which the kit proves. R13's own kit fires its pin toggler with synthetic clicks (`R13_reorder_guard.sh:31`).

3. **R10: only the no-identity (orange) dot is checked.** The green (identity set up) state of the dot on the menu icon is not exercised (`R10_items.sh:28`).

4. **R12: only font mode is exercised.** The kit tests Ctrl −/+ in font mode, not "Zoom whole app with CTRL -/+". By the code, app zoom reaches the grid only through a resize, and a resize while locked goes to `fitLockedTerminal` (`renderer/app.js:7852`), so the grid should hold. That is not proven by a check.

5. **U2: "played back" is checked by the button being hidden.** The kit does not resize the window during scrollback. "Ended" is checked as `size-lock-state .active == false` (a declared soft change). The code returns before any `session.resize` in playback mode (`renderer/app.js:7815-7821`).

6. **The kit pins the sidecar to a checkout path.** `acceptance/activate:42` defaults `ZXTERM_CORE_BIN` to `/zp/zdata/zeev/github/zbterm/npm/zxterm-core-linux-x64/zxterm-core`, because the packaged build carries no sidecar. So "the packaged app boots" holds only with that override, and the kit is tied to this host and checkout.

7. **bs/R11 runs close to the 240 s per-script budget.** It took 214 s here (the builder measured 215 s). Any slowdown would turn it into a timeout FAIL under a 240 s cap.

8. **The current session also appears as a buffer-match row while searching** (`shots/R3.png`: shot-rec is under both "Current session" and "Session buffer matches"). This is earlier buffer-search behaviour, which that kit expects (bs/R5 asserts the current session among the buffer rows). It is outside R3's scope and is recorded only for the reader.

9. **AGENTS.md is out of date.** It names `docs/projects/README.md`, `docs/register.md` and `docs/decisions.md`, which are absent since b9a1c7b (the builder flagged this in `status--verifying.md` *Open*). It is a descriptive statement in AGENTS.md that is now false. The verifier did not change it; it is the maintainer's call.

10. **Lint is clean apart from 95 `require-await`-style warnings.** For example `electron/debug-server.js:118`, `forge.config.js:318`. These were already there and are not errors.
